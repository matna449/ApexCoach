# Classification stays pure (hrv_30d_avg_ms as a parameter); HRV Delta boundaries resolved from Neutral's stated inclusive range

Building F05.1 surfaced that `hrv_30d_avg_ms` isn't part of `WhoopDailyPayload` — it only exists as a `daily_metrics` column, meant to be computed from the last 30 days of stored WHOOP HRV readings per SDD §5.4. ADR-0006 built `metrics_repository.get_daily_metrics_range()` specifically anticipating this ticket closing that loop. We're not closing it here: `classify_daily_inputs()` takes `hrv_30d_avg_ms` as a plain parameter and stays pure, matching this ticket's own acceptance criteria ("Unit tests cover every band boundary" — unit, not integration). Computing the rolling average itself is a different kind of problem — 30-day window semantics, whether today's own reading counts, what happens with fewer than 30 days of history — genuinely separate from exact-threshold classification, and left as an explicit, documented gap for whichever ticket wires the full morning flow together. **Resolved by docs/adr/0021** (F11.4, #44): the window excludes today, and a cold-start policy (< 7 valid days) forces a `HRV_NEUTRAL` band via a delta of 0 rather than classifying against a noisy 1-6 day average — without changing `classify_daily_inputs()`'s signature.

Logic Spec §2.2's HRV Delta table is internally ambiguous at its boundaries: Positive is "> +5", Neutral is "-5 to +5", Negative is "-5 to -10", Strong Neg is "< -10" — Neutral and Negative both claim -5 falls in their range. We resolved this from Neutral's stated inclusive wording: `-5 to +5` reads as a closed interval, so Neutral owns both boundary values (`-5 <= delta <= +5`), Negative is `-10 <= delta < -5`, and Strong Neg is `delta < -10` (matching its own literal "< -10"). The classifier is implemented as `delta > 5 → POSITIVE`, `-5 <= delta <= 5 → NEUTRAL`, `-10 <= delta < -5 → NEGATIVE`, `delta < -10 → STRONG_NEG` — four non-overlapping, exhaustive ranges. Unit tests cover exactly ±5 and exactly -10 explicitly, per this ticket's own acceptance criteria.

Alternative considered, for the boundary ambiguity: treat "-5 to -10" as authoritative and let Negative own -5, narrowing Neutral to `-5 < delta < +5`. Rejected because Neutral's range is stated with the less-negative bound written the conventional way (`-5 to +5`, low-to-high) while Negative's is written high-to-low (`-5 to -10`) — reading Negative as descriptive prose ("from mild negative down to strong negative") rather than a precise interval is more consistent with how the rest of the table is written, and Positive's own ">+5" (strict) implies Neutral's "+5" endpoint is deliberately inclusive to avoid a gap between Neutral and Positive — the same logic extends to the -5 boundary.
